           assets/js/app.js

Upload and you're done. Worker untouched — no redeploy, so the secrets
stay where they are. index.html unchanged.

WHAT WAS WRONG

A dates row showed the day, the title, the time and the venue. The
calendar's description was fetched, carried all the way through the
Worker and handed to the browser on every event — and then thrown away
at the last step. /dates has always returned it:

  { title, where, description, startMs, endMs, allDay, start }

renderDates() read three of those seven fields.

1. THE DESCRIPTION, UNDER THE VENUE  (app.js, style.css)

New .row__desc, a third line in column 2 after .row__sub. Rendered
only when the event has a description — an event without one looks
exactly as it did before, no empty element, no extra gap.

Colour is --ink-40 rather than the venue's --ink-64, so the row reads
title -> place -> detail top to bottom instead of two lines of equal
weight. --ink-40 measures 4.59:1 on --paper, which clears AA for body
text at this size. Line length is capped at 62ch: on a wide monitor an
uncapped paragraph would run the full width of the section and read
worse than the same text in a narrower column.

2. TWO LINES, THEN "MORE"  (app.js, style.css)

These are Google Calendar descriptions and they run to a paragraph.
The Feria del Libro entry is 300 characters; the Décimo Piso one is a
single line. Shown in full, one event buries the three below it.

.row__desc clamps to two lines. Where there is more behind the clamp,
JS adds a MORE / MÁS toggle that unclamps it. Where there isn't, there
is no toggle — CSS can't ask "did this overflow", so the JS measures
scrollHeight against clientHeight after the rows are in the document
and adds the button only where the answer is yes.

The toggle is a separate <button>, not the paragraph itself. A button's
accessible name is its text content, and 300 characters of Spanish
prose is not a usable name for a control. It carries aria-controls and
aria-expanded, so it works from the keyboard and announces its state.

Padding on the button is a thumb target, not spacing: at .6875rem the
label alone is a 13px-tall tap area. Negative margins pull the enlarged
box back into line, so the target is 45x30 and the layout doesn't move.

3. THE MID-WORD CUT  (app.js)

The Worker does .slice(0, 300) on the description and cuts wherever the
300th character lands. On the live feed that is mid-word:

  ...en los edificios vacíos del Berlín recién reunificado, u

tidyDesc() pulls back to the last word break and ends on an ellipsis:

  ...en los edificios vacíos del Berlín recién reunificado…

It measures the raw string before collapsing whitespace, not after. A
calendar entry with blank lines in it normalises down to well under 300
characters, so checking the tidied length would report a truncated
description as untouched — which is exactly what the first pass did.

If the 300 characters hold no word break at all — a URL, a wall of
hashtags — nothing is dropped and the ellipsis is simply appended.

4. RE-MEASURING ON RESIZE  (app.js)

A narrower column fits fewer words, so a description that needed no
toggle in landscape needs one in portrait. Without this a rotated phone
shows two clamped lines and no way to reach the rest. A debounced
resize re-runs the same measurement; open rows are skipped, since an
unclamped paragraph always measures as fitting and re-measuring one
would take its own toggle away.

VERIFIED  (headless Chromium, desktop 1280 and mobile 390, en + es)

  Long description   clamped to 2 lines, toggle present, opens and
                     closes by mouse and by Enter, aria-expanded
                     tracks the state
  Short description  rendered in full, no toggle
  No description     no element at all, row unchanged
  Language switch    toggle re-labels MORE <-> MÁS
  Resize 1280 -> 360 the mid-length row gains a toggle; back to 1280
                     it loses it again, and a row left open stays open
  Toggle target      45 x 30 px, label aligned with the venue above it
  Console            no errors, no duplicate ids

NOT DONE, AND WHY

  RAISING THE 300-CHARACTER CAP.  It lives in the Worker, and the
  Worker deploys from the Cloudflare dashboard — its secrets do not
  survive a redeploy. The cut is now clean at the word, which is the
  part a reader sees. Worth revisiting only alongside a Worker change
  that has to happen anyway.

  ANIMATING THE EXPAND.  A height transition on auto-height content
  needs a measured max-height and a second reflow, and it would want a
  prefers-reduced-motion branch on top. The clamp is a reading aid, not
  a reveal.

  LINKIFYING URLS IN THE DESCRIPTION.  The text is escaped through
  esc() and stays escaped. Turning fetched calendar text into live
  markup is the one change here that could hurt, and no current entry
  needs it.
