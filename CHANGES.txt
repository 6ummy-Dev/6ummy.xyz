CLOUDFLARE DASHBOARD — five steps, in this order

1. Security headers (fixes: anti-framing P2, headers-meta-only P2)
   Rules → Overview → Create rule → Response Header Transform Rule.
   Name: security headers
   If: Custom filter expression → Edit expression:
     (http.host eq "6ummy.xyz" and not starts_with(http.request.uri.path, "/cdn-cgi/"))
   Then: "Set static", one row each:

   Content-Security-Policy
     default-src 'self'; base-uri 'none'; object-src 'none'; script-src 'self' https://static.cloudflareinsights.com; style-src 'self'; font-src 'self'; img-src 'self' data: https://i.ytimg.com https://i.discogs.com https://img.discogs.com; connect-src 'self' https://6ummy-api.6ummy-xyz.workers.dev https://cloudflareinsights.com; frame-src https://www.youtube-nocookie.com https://player.twitch.tv https://w.soundcloud.com; form-action 'self' mailto: https://formspree.io https://api.web3forms.com; frame-ancestors 'none'
   X-Frame-Options          DENY
   Referrer-Policy          strict-origin-when-cross-origin
   Permissions-Policy       camera=(), microphone=(), geolocation=(), payment=(), usb=()
   Cross-Origin-Opener-Policy  same-origin

   Deliberately NOT set:
   - Cross-Origin-Resource-Policy: logo.gif / logo-sm.gif / logo-static.png
     are hotlinked as avatars elsewhere; CORP same-origin would block them.
   - Cross-Origin-Embedder-Policy: would break the YouTube / Twitch /
     SoundCloud players and the Discogs sleeves.
   - Permissions-Policy entries for fullscreen / autoplay: the players
     need them.

   Upload the build FIRST — the header carries mailto: in form-action,
   and the 404 page keeps its own tighter meta CSP (browsers apply both;
   the tighter one wins).

   Check from outside (your own curl.exe is fine for headers):
     curl.exe -sI https://6ummy.xyz/
     curl.exe -sI https://6ummy.xyz/assets/css/style.css
   All five headers should be on both. If they're on style.css but NOT
   on / , the 6ummy-agent-edge Worker's response is skipping the rule:
   tell me and I'll give you the five-line addition for that Worker
   (copy its code out of the editor first, as always).

2. HSTS to one year + preload (fixes: HSTS P2)
   SSL/TLS → Edge Certificates → HTTP Strict Transport Security → Change:
   Max-Age 12 months, Apply to subdomains ON, Preload ON, No-Sniff ON.
   The old reason to hold preload back (registrar transfer pending) closed
   on 15 Aug. Submitting at hstspreload.org is a separate, hard-to-undo
   step — only do it if you want the domain in browsers' built-in list.

3. CAA (fixes: CAA P2)
   DNS → Records → Add record, type CAA, name @, three records:
     Tag "Only allow specific hostnames"  value pki.goog
     Tag "Only allow specific hostnames"  value letsencrypt.org
     Tag "Only allow specific hostnames"  value ssl.com
   Cloudflare adds the CAs its Universal SSL needs on its own once any
   CAA record exists, so the edge cert keeps renewing. Don't touch MX.

4. Beacon delivery (fixes: Radar CORS P2 — a check, not a change)
   Analytics & Logs → Web Analytics → 6ummy.xyz. If real visits show up,
   close it: Radar's failure was its own signature-agent header. If it
   reads zero while you know people visited, tell me.

5. Purge + ping

DECLINED — with the reason

P2  Crate image delivery (300 KiB). Discogs serves 150 or 600, nothing
    between, on signed URLs (settled). The suggested DPR ≥ 2 gate would
    only win the lab number — Lighthouse's phone is 1.75 DPR — and show
    soft sleeves on every real 1.25–1.75 screen. Resizing through
    Cloudflare Images means running Discogs's signed URLs through a new
    product for a number. Merit decline.

P2  Minify JS / CSS (11 + 5 KiB). No build step is the site's premise;
    content.js is hand-edited. Assets already go out compressed. Same
    decline as August.

P2  4 h cache on own assets. A long TTL on file names that don't change,
    edited by hand in the GitHub web UI, is how a stale content.js got
    served for weeks. ?v= tags would need a hand bump on every edit.
    Merit decline.

P2  Beacon legacy JS (10 KiB). Cloudflare's code, not ours. The only
    lever is dropping analytics, which you turned on on purpose (26 Aug).

P2  PWA service worker + offline. The installable half is done above.
    An offline copy of a page whose point is live status and dates would
    show stale data as current, and a SW cache on top of a hand-edited
    content.js is the stale-file problem again. Expect PWA 5/8.

—   Proxying sleeves through the Worker to drop Discogs's __cf_bm cookie.
    Discogs throttles per Cloudflare egress IP; every sleeve through the
    Worker would hit that. The disclosure fixes the P1 honestly.

—   formEndpoint (Formspree / Web3Forms). New third-party signup. The P1
    is fixed by putting the address on the page.
