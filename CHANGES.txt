WHAT WAS WRONG

A dates row showed the day, the title, the time and the venue. The
calendar's description was fetched, carried all the way through the
Worker and handed to the browser on every event — and then thrown away
at the last step. /dates has always returned it:

  { title, where, description, startMs, endMs, allDay, start }

renderDates() read three of those seven fields. And there was no way to
keep a date: a visitor who wanted to remember a gig had to type it into
their own calendar by hand.

1. THE DESCRIPTION, UNDER THE VENUE  (app.js, style.css)

New .row__desc, a third line in column 2 after .row__sub. Rendered
only when the event has a description — an event without one looks
exactly as it did before, no empty element, no extra gap.

Colour is --ink-40 rather than the venue's --ink-64, so the row reads
title -> place -> detail top to bottom instead of two lines of equal
weight. --ink-40 measures 4.59:1 on --paper, which clears AA for body
text at this size. Line length is capped at 62ch: on a wide monitor an
uncapped paragraph would run the full width of the section and read
worse than the same text in a narrower column.

2. TWO LINES, THEN "MORE"  (app.js, style.css)

These are Google Calendar descriptions and they run to a paragraph.
The Feria del Libro entry is 300 characters; the Décimo Piso one is a
single line. Shown in full, one event buries the three below it.

.row__desc clamps to two lines. Where there is more behind the clamp,
JS adds a MORE / MÁS toggle that unclamps it. Where there isn't, there
is no toggle — CSS can't ask "did this overflow", so the JS measures
scrollHeight against clientHeight after the rows are in the document
and adds the button only where the answer is yes.

The toggle is a separate <button>, not the paragraph itself. A button's
accessible name is its text content, and 300 characters of Spanish
prose is not a usable name for a control. It carries aria-controls and
aria-expanded, so it works from the keyboard and announces its state.

3. THE MID-WORD CUT  (app.js)

The Worker does .slice(0, 300) on the description and cuts wherever the
300th character lands. On the live feed that is mid-word:

  ...en los edificios vacíos del Berlín recién reunificado, u

tidyDesc() pulls back to the last word break and ends on an ellipsis:

  ...en los edificios vacíos del Berlín recién reunificado…

It measures the raw string before collapsing whitespace, not after. A
calendar entry with blank lines in it normalises down to well under 300
characters, so checking the tidied length would report a truncated
description as untouched — which is exactly what the first pass did.

If the 300 characters hold no word break at all — a URL, a wall of
hashtags — nothing is dropped and the ellipsis is simply appended.

4. RE-MEASURING ON RESIZE  (app.js)

A narrower column fits fewer words, so a description that needed no
toggle in landscape needs one in portrait. Without this a rotated phone
shows two clamped lines and no way to reach the rest. A debounced
resize re-runs the same measurement; open rows are skipped, since an
unclamped paragraph always measures as fitting and re-measuring one
would take its own toggle away.

5. ADD TO CALENDAR  (app.js, style.css)

Every upcoming date now has an ADD TO CALENDAR / AGREGAR AL CALENDARIO
button that hands over a .ics file. Not a calendar.google.com link: that
would have been one line, but it only serves Google users and it walks a
visitor into a tracker from a site whose whole premise is that it hasn't
got one. The .ics opens in Calendar, Google, Outlook, Thunderbird — and
it is built here, in the browser, from event data already on the page.
No second request, no third party, no key.

Past dates get no button. A calendar file for a gig that already
happened is an entry in the past, which is what the Recent list is for.

The file is a real RFC 5545 VEVENT, which mostly means getting the dull
parts right:

  ESCAPING       Backslash, semicolon and comma are delimiters inside a
                 property value. Unescaped, "Denk y Sven von Thülen
                 (Alpha Decay), es la historia" ends the DESCRIPTION at
                 the comma and the rest becomes a bad property name.

  FOLDING        Lines fold at 75 OCTETS, not characters. Folding on a
                 character count splits the í in "Berlín" down the
                 middle, and an importer handed half a code point
                 rejects the file rather than guessing. Surrogate pairs
                 are kept together for the same reason — the disco ball
                 in "DMF + CS + FoD" is one character to a reader and
                 two units to a for-loop.

  ALL-DAY        DTSTART;VALUE=DATE, and DTEND is the day AFTER: a date
                 DTEND is exclusive, so the obvious version produces an
                 event that ends the moment it begins. The Worker
                 anchors all-day events at UTC midday precisely so a
                 timezone shift can't move them off their own date, so
                 the UTC parts are what to read back out.

  UID            Stable: startMs + a slug of the title. Saving the same
                 gig twice updates the entry the reader already has
                 instead of leaving them two.

The description written into the file is the tidied one, so a saved
event doesn't carry the Worker's mid-word cut around in someone's
calendar forever.

If Blob or createObjectURL is missing the button is never rendered,
rather than rendered and dead.

6. YELLOW EVENT TITLES  (style.css)

.row--date .row__main is now --live. Dates only. .row__main is also the
record name in Crate and the link name in Elsewhere, and yellow already
carries the section indices, the primary button, focus rings and the
mark — spend it on every row and the page has no accent left. An event
title is the one row value that names something happening, which is
what the colour has meant since the live flood.

12.74:1 on --paper. The venue and description below it are unchanged,
so the row now reads yellow -> --ink-64 -> --ink-40, brightest first.

7. THE CONTROL STRIP  (app.js, style.css)

MORE and ADD TO CALENDAR share a .row__acts flex strip rather than
stacking. A row with neither is display:none, so an event with a
one-line description and no button keeps exactly the spacing it had
before any of this existed.

Padding on the buttons is a thumb target, not spacing: at .6875rem the
label alone is a 13px-tall tap area. The negative margins sit on the
strip and pull it back by that padding, so the first label still lines
up with the venue above it — the targets grow, the layout doesn't move.

Both buttons carry the event title in a visually-hidden span. Eight
buttons all named "Add to calendar" are eight identical rows to someone
listening rather than looking. The visible word stays first in the
accessible name, so voice control still matches on what is on screen.

NOT DONE, AND WHY

  RAISING THE 300-CHARACTER CAP.  It lives in the Worker, and the
  Worker deploys from the Cloudflare dashboard — its secrets do not
  survive a redeploy. The cut is now clean at the word, which is the
  part a reader sees. Worth revisiting only alongside a Worker change
  that has to happen anyway.

  A "SUBSCRIBE TO ALL DATES" LINK.  The natural companion to the per-
  event .ics, and it needs the calendar's own feed URL — which means
  CALENDAR_ID, which is a Worker secret and deliberately not sent to
  the browser. Doing it properly means a Worker route that proxies the
  .ics, so: same redeploy question. Parked, not rejected.

  ANIMATING THE EXPAND.  A height transition on auto-height content
  needs a measured max-height and a second reflow, and it would want a
  prefers-reduced-motion branch on top. The clamp is a reading aid, not
  a reveal.

  LINKIFYING URLS IN THE DESCRIPTION.  The text is escaped through
  esc() and stays escaped. Turning fetched calendar text into live
  markup is the one change here that could hurt, and no current entry
  needs it.
