1. ANONYMOUS FALLBACK — aimed straight at tonight's blocker

   When the authenticated call is throttled AND there is no stored copy,
   the Worker now tries once more without the token.

   That looks backwards: anonymous is a LOWER ceiling, 25 against 60, on
   the same shared IP. The ceiling is not the point. Without an
   Authorization header Cloudflare will actually honour cf.cacheTtl, so
   the request can be answered from Cloudflare's own cache and never
   reach Discogs at all. With the shared bucket saturated the way it was
   all evening, a cache hit is the only door left open.

   Gated so it can only ever fire cold — once a copy is stored, a
   throttled refresh serves stale and makes no extra call. Response
   carries fallback:"anonymous" and limit.cfCache so you can see which
   door it came through.

2. warm() NOW CHECKS FRESHNESS FIRST

   It used to fetch on every tick regardless. Fine at every 15 minutes,
   rude at every minute — and raising the cron frequency is the obvious
   next lever. Thresholds: crate 30 min, dates 10 min, youtube 60 min.
   Below that a tick spends nothing.

   This is the prerequisite for moving the cron to `* * * * *`. With it
   in place, per-minute is safe: it hammers only while stale, then backs
   off to ~2 calls/hour once healthy.
